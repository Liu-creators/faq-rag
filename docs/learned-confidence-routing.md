# 后续优化：可学习的置信度分流

> 状态：思路记录，尚未实现。  
> 相关代码：`src/faq_rag/services/ask/pipeline.py`（当前硬阈值 `0.90` / `0.70`）

## 现状

FAQ 命中后按稠密余弦相似度做三段分流：

| 条件 | 路由 |
|------|------|
| `score ≥ 0.90` | 原样返回 FAQ 标准答 |
| `score ≥ 0.70` | FAQ 锚定 LLM 改写 |
| 否则 | 文档 RAG |

这两个阈值是占位常量：余弦分不是校准概率，换 embedding / FAQ 分布后最优切点会漂；且只用 top1 分数，信号偏弱。

## 核心想法

真正要学的不是「一个置信度数字」，而是：

> 给定检索特征，这条命中该走哪条路由：`verbatim` / `rewrite` / `doc_rag`。

置信度区间可以、也应该从数据中学出来，而不是长期靠拍脑袋阈值。

从业务上看，这和**意图识别**是同一类问题：判断用户问的是不是某个已知 FAQ 意图、以及该多确定地走 FAQ 路径。差别主要在建模方式（见下）。

## 建议路线（由轻到重）

1. **标定阈值**  
   用小规模标注集扫描切点（控制误原样率、最大化有效命中）。先把 `0.90` / `0.70` 换成数据驱动的静态阈值。

2. **线性 / 浅层模型（优先）**  
   多特征 → logistic / 有序回归 → 路由概率。标注量小（几百条级）即可，可解释、易上线。适合作为 FAQ 门控的主方案。

3. **深度学习（后续）**  
   有规模日志、且浅模型不够时再上。这里有两条常见路，别混成一件事：

   | 路线 | 在做什么 | 和意图识别的关系 |
   |------|----------|------------------|
   | **A. 检索后打分 / 路由头** | 先召回候选 FAQ，再用 cross-encoder 或小分类头判断「是否匹配 + 走哪条路由」 | 偏「匹配置信度 / 路由分类」，仍挂在检索后面 |
   | **B. 文本分类意图识别** | 直接 `query → FAQ_id / intent / 其他(OOD)` | 经典意图识别；可部分替代「检索 + 硬阈值」，FAQ 很多时通常仍要和检索结合 |

   文档里说的「后续深度学习」**可以**做成 B（训练文本分类做意图识别），也可以做成 A（加强现有检索门控）。对本项目，更自然的演进是：先 A 校准路由，数据与 FAQ 规模上来后再评估是否上 B。

## 可学特征（示例）

- top1 稠密余弦
- top1 − top2 margin
- BM25 / RRF 分
- 命中标准问 vs 相似问
- 问句长度、类目先验

## 标签来源

业务日志 + 人工确认：该原样 / 可改写 / 应走文档。比纯相似度更接近真实决策成本（误原样通常贵于误改写）。

## 上线形态（设想）

```text
P(verbatim) ≥ τ1  → 原样
P(rewrite)  ≥ τ2  → FAQ 改写
否则              → 文档 RAG
```

τ 仍可按误判代价单独调；模型负责把「原始相似度」校准成「路由置信度」。

## 小结

- 短期：用标注标定现有硬阈值即可。
- 中期：多特征 + 线性路由分类器，替换 `CONFIDENCE_*` 常量门控。
- 长期：数据量上来后再考虑深度模型。
